# 手机照片备份（PhonePhotoBackup）

一个 Windows 桌面小程序：用你手机里的相册（DCIM），一键备份到电脑，然后按时间浏览。

- **单文件 exe**，不用装 Python、不用装 adb、不用联网
- **有线无线都行**：插数据线即可；Android 11+ 还能走 Wi-Fi（无线调试），不用插线
- **多台手机**：每台一个目录，可以分别看、也可以混着看，还能一次把几台一起备份
- **只读**：全程只用 `adb devices` / `content query` / `pull` / `getprop` 这几类只读命令，代码里不存在任何写手机的操作
- **增量**：跨设备、跨目录判重；拔线 / 掉线中断后重新点一次就从断点继续
- **掉线立刻停手**：只停掉线那一台，其余继续；已拷的文件一个不丢
- **按拍摄时间归档**：`<备份目录>\<设备>\<类别>\2024\2024-03-15\IMG_xxx.jpg`
- **打开先看本机**：默认停在「本机文件」，每次启动自动重扫一遍电脑上的图片视频
- **右键能复制、滚轮能缩放**：缩略图右键第一项就是「复制」；大图里滚轮放大，按住左键拖动平移

## 快速上手

| 步骤 | 做什么 |
|---|---|
| 1 | 手机插上数据线，USB 用途选 **文件传输 / MTP** |
| 2 | 手机开启 **开发者选项 → USB 调试**；弹出「允许 USB 调试吗」时点**允许**（勾「一律允许」） |
| 3 | 双击桌面上的 **「手机照片备份」** → 点 **刷新** → 点 **开始备份** |

不想插线的话看 **无线备份（Wi-Fi）** 那一节 —— Android 11+ 配对一次之后就不用再插了。

备份完成后，左侧会按 `年 → 月` 列出照片（点年份看全年，点月份看当月）。

程序**一打开默认停在「查看 → 本机文件」**，并且每次启动都会自动把本机库重扫一遍 ——
新存进「图片 / 桌面 / 下载 / 文档 / 视频」的图，开机就能看到，不用先点刷新。
想切回手机备份，点顶栏「查看」选「全部设备」或具体某台手机即可。

### 浏览操作

| 操作 | 效果 |
|---|---|
| 单击缩略图 | 设为键盘焦点（蓝色描边） |
| `↑` `↓` `←` `→` | 在网格里移动焦点，自动滚进视野 |
| `Enter` / 双击 | 打开大图 |
| 大图两侧的三角按钮 | 上一张 / 下一张（鼠标点） |
| 大图内 `←` `→` | 上一张 / 下一张（键盘） |
| 大图内 `Shift` + `←` `→` | **按天翻**，一次跳过当天其余照片 |
| 大图上**按住鼠标左键** | 动态照片：播放里面藏着的那段视频 |
| 大图上**滚轮** | 放大 / 缩小（1.0×–6.0×，以光标为中心） |
| 放大后**按住左键拖动** | 平移画面；缩回 1.0× 自动回到居中 |
| 大图上打开视频文件 | **自动在窗口内播放**，点一下画面暂停 / 再点继续 |
| 拖动视频下方的进度条 | 跳到任意位置（暂停中也能拖） |
| `Esc` | 关闭大图 |
| 右键缩略图 | **复制** · 用系统程序打开 · 资源管理器定位 · 移到回收站 |
| 鼠标滚轮 | 滚动网格 |

大图窗口里翻页是**沿着全库时间线**走的：从最新一张一路翻到最早，跨天、跨月、跨年都不会停。
状态栏右侧显示的是你在全库中的位置（如 `5 / 1778`），不再限于当前选中的那个月。

顶栏的 **刷新** 一次做两件事：**重扫本地库**（新落进来的照片立刻出现在时间柱上）和
**重新识别手机**。以前它只管后者，新增的文件得走「更多 → 重新扫描本地库」才看得到 ——
点了「刷新」却不见新照片，很容易以为没扫到。

缩略图一律**居中裁剪成正方形**，所以每张大小一致、网格整齐；原图不受影响，看大图时仍是完整画面。

菜单、下拉、弹窗全是自绘的圆角白卡（系统原生控件在 Windows 上是直角灰皮，跟这套白底对不上）：
右键菜单、「更多 ▾」、设备下拉都是白底 + 细边 + 圆角，hover 垫一层浅蓝，危险动作用红字。
**点菜单以外的任何地方、按 `Esc`、或窗口失去焦点**，菜单都会关掉。

**移到回收站**只动电脑上的副本。删完那一张会**立刻**从网格里消失，那天的计数跟着减；
整天删空后月份会从左侧时间柱上直接消失，并自动跳到还有照片的最近一组。

切月份**不重建格子**：格子建一次放进池子反复用，换组只改内容。实测 400 格的组
同一组重画约 2ms、换到没看过的组约 200ms，而且切换过程中屏幕不会空一下。
缩略图按路径缓存最近两组（约 90MB 内存），所以来回切月份不用重新解码。

缩略图上屏走 **PPM**（无压缩裸像素）而不是 PNG：PNG 要 zlib 压缩 + base64 + Tk 再解一遍，
单张 4.7ms，一屏 400 张就是**近两秒的主线程冻结**；PPM 单张 0.5ms。
消息泵一轮也只处理 24 张，剩下的下一轮继续，所以几百张图填进来时界面一直能响应。
实测同一屏 400 张：旧做法最长冻 2.7 秒，现在 0.1 秒。

> 手机上不开 USB 调试的话，`adb devices` 永远看不到设备 —— 这是最常见的失败原因。

## 无线备份（Wi-Fi）

不想每次插线的话，Android 11 及以上可以让 adb 走 Wi-Fi，拔掉数据线也能备份。
本程序面向 **Android 14 / 15**，走的是系统自带的「无线调试」。

### 首次：配对一次

| 步骤 | 在哪儿做 | 做什么 |
|---|---|---|
| 1 | 手机 | 设置 → 开发者选项 → **无线调试** → 打开 |
| 2 | 手机 | 点 **「使用配对码配对设备」**，屏幕上会出现 `IP:端口` 和一组 **6 位数字** |
| 3 | 电脑 | 顶栏点 **「无线」**，在面板里点 **「重新发现」** |
| 4 | 电脑 | 把 6 位数字填进「配对码」，点 **「配对并连接」** |

配对只需要做一次 —— 手机记住了这台电脑。

### 以后：点一下就连

手机把「无线调试」开着，电脑点「无线」→「连接」即可（先点「重新发现」让它自己找也行）。
连上之后设备下拉框里会出现 `192.168.31.100:37001` 这样的条目，后面的「开始备份」和有线完全一样。

### 为什么要点「重新发现」

Android 11+ 的**配对端口和连接端口不是同一个，而且每次开关「无线调试」都会重新随机** ——
去手机上抄 `IP:端口` 很烦。所以面板用 mDNS（`adb mdns services`）自动找，你只需要抄那 6 位数字。

配对成功后它会自动再发现一次、拿连接端口去连，两步并作一步。
路由器如果开了「AP 隔离」或者禁了组播，mDNS 就会一无所获 —— 那就把手机上显示的
「IP 地址和端口」手动填进地址栏再点「连接」。

### 掉线会怎样

**立刻停手**，不会傻等：

- 拉文件的整个过程中每 5 秒探一次手机还在不在。掉了就**杀掉正在跑的 adb 进程、删掉半截的 `.part`、马上中止**
  （无线下最恶心的情况是手机突然关机，电脑这头的 TCP 连接半开、`adb pull` 一直挂着，
  不看着的话会干等 30 分钟才超时）
- 界面弹一个**应用内样式的提示框**（不是系统那种灰框），告诉你已经拷完多少个，
  并给一个 **「重新连接」** 按钮，一点就打开无线面板
- 连续 5 个文件都拉不下来（那不是掉线，是文件本身有问题）同样会停下来，免得白跑几万个

已经拷到电脑上的文件**全部保留**，手机上也不会少任何东西。重新连上后再点一次「开始备份」，
已备份的会自动跳过 —— **断点续传的粒度是单个文件**，这个特性有线时代就有了，无线下更值钱。

### 有线还是无线

| | 有线 | 无线 |
|---|---|---|
| 要不要插线 | 要 | 不要 |
| 速度 | 快（USB 2.0 实测约 20–30 MB/s） | 看 Wi-Fi，一般 8–20 MB/s |
| 首次全量（十几 GB） | 几分钟 | 十几分钟到半小时 |
| 日常增量（几十张） | 几秒 | 十来秒 |
| 稳不稳 | 最稳 | 手机息屏过久可能会掉 |

**结论**：日常增量用无线很划算；一次性几百 GB 的全量，还是插线更快更稳。

> 无线调试走的是 **TLS + 配对码**，比老式的 `adb tcpip 5555`（明文）安全。
> 本程序不会替你去开 `tcpip`，也不会动手机上的无线调试开关 —— 那些都在手机上手点。
> 它只调用 `adb pair` / `adb connect` / `adb disconnect`，一个字节的媒体数据都不碰。

> ⚠️ **不是每台手机都有「无线调试」。** 华为官方文档明确写了 EMUI 10.0–15.0、
> HarmonyOS 2.0–4.3 **没有这个设置项**，只能用数据线；荣耀部分版本（如 Magic UI 4.1）
> 也一样。HarmonyOS NEXT（5/6）更进一步 —— 它已经不是 Android，**adb 完全不认**。
> 所以无线是加分项，**有线才是所有品牌都通的那条路**。

## 多台手机

### 各看各的

顶栏「查看」那个下拉就是切设备：

- **全部设备** —— 所有手机的照片合成一条时间线，方便总览
- **全部（含本机文件）** —— 手机备份的 + 这台电脑上的，混成一条时间轴
- **本机文件** —— 只看这台电脑上的图片视频（见下面「本机文件」一节）
- **某台手机** —— 只看它的

切过去之后，左侧的年月树、缩略图网格、大图的 `←` `→` 翻页**都只在这台设备的范围内**，
不会翻着翻着跳到另一台手机的照片上。

> 混合视图里同名文件会同时出现两张（两台手机各拍过 `IMG_20240101_120000.jpg`）——
> 它们本来就在不同目录下，这是正常的。

### 一起备份

同时连着好几台时，点「开始备份」会先弹一个列表让你勾这次备份哪几台，
然后**按顺序一台一台地备份**（USB 和无线混着插也认）。

**中途某台掉线只停那一台**，其余照常备份完，最后统一告诉你哪台掉了、各拉了多少。

### 靠什么认出「这是同一台手机」

用手机自己的 `android_id`（`adb shell settings get secure android_id`），**不是 USB 序列号**。
因为同一台手机 USB 插着叫 `BQEYBIM7V4ZH4LDA`、无线连着叫 `192.168.1.5:37001`，
序列号完全对不上，只有 `android_id` 永远不变。

目录名取自手机的市场名（`ro.product.marketname`）：`REDMI K80 Ultra` → `REDMI-K80-Ultra`。
想换名字走 **更多 → 重命名设备目录…** —— 改完应用会记住，下次备份不会另建一个旧名字的目录。

### 从老结构升级过来

如果库还是老的 `<备份目录>\2024\2024-03-15\` 结构，启动时会问一次要不要归入设备目录；
也可以随时走 **更多 → 把老照片归入设备…**。它会：

- **先把清单摊给你看**（多少个文件、分成哪几类），你点确认才动手
- 类别优先用手机上的真实目录判断；手机没连就按文件名猜
- 只移动电脑上的副本，**手机完全不受影响**
- 目标已有同名文件就跳过，**绝不覆盖**
- 搬完只清理空掉的日期目录，不删任何照片
- 清单落在 `<备份目录>\.migration-log.json`，万一要回滚有据可查

## 本机文件（这台电脑上的图片视频）

「查看」里选 **本机文件**（这也是程序启动时的默认视图），就能在同一个界面里看这台电脑上的
图片和视频，同样按拍摄时间排进时间柱。**只读展示：应用不移动、不改名、不复制，也永远不会碰你手机上的东西。**

扫的是用户目录下这几个位置：

```
Pictures   Desktop   Downloads   Documents   Videos   OneDrive
```

几条规则：

- **QQ 目录整个跳过。** 你机器上 `Documents\Tencent Files` 里有 1.4 万个媒体文件，
  九成是表情包（Emoji）、缩略图（Thumb）和程序图标 —— 收进来只会把时间柱撑满垃圾。
- **其他垃圾按目录名过滤**：表情包、缩略图、缓存、程序图标、头像、在线状态图标。
  实测你的机器：14321 个 → **148 个**（截图 94 · 下载 36 · OneDrive 7 · 游戏录像 9 ·
  企业微信 1）。
- **时间「拍摄时间优先」**：先读 EXIF（手机拍的、相机导入的），没有就用文件修改时间。
  截图、下载的图、聊天图基本都没有 EXIF —— 你这批实测命中率 0%，所以实际都走文件时间。
- **不会把备份过的再收一遍**：备份根（`D:\PhonePhotos`）整个排除。
- **每次启动都扫一遍**（实测 200 来个文件 0.2 秒），不做跨次启动的持久缓存 ——
  本机文件随时会被增删，沿用旧列表会「新图看不见、删掉的还挂着」；
  点顶栏 **刷新**（或 **更多 → 重新扫描**）也会重扫。
- **删除进 Windows 回收站**（可还原）。注意这里删的是**电脑上的原文件**，所以右键菜单和
  确认框写的是「移到回收站」，而不是手机备份那边的「移到回收站（仅电脑上的副本）」。

## 动态照片（手机上的「动图」）

小米/红米、Google、三星等相机拍的**动态照片**（文件名常以 `MVIMG_` 开头），本质是
**一张 JPEG 末尾多粘了一段 MP4** —— 手机相册长按就能看到的那段小视频。

本程序的处理：

- **备份**：整个文件原样拉过来，照片和那段视频都在，一个字节没动
- **识别**：读文件头的 XMP，取 `Item:Mime="video/mp4"` 的 `Item:Length`（旧格式 `GCamera:MicroVideoOffset` 也认），
  算出内嵌 MP4 的起止位置；起点处的 `ftyp` box 用来复核
- **浏览**：网格和默认大图显示的是**静态主图**（和资源管理器一致）
- **看动图**：打开大图后**按住鼠标左键不放**，那段视频**就在当前窗口里直接播放**，松手即停 —— 和手机上一样

> **为什么不会卡**：用 Windows 自带的 `mfplay.dll`（Media Foundation，Windows 7 起随系统提供），
> 把画面直接渲染到查看器里的一个子窗口上 —— 硬件解码 + EVR 渲染，Python 这边**一个像素都不碰**。
> 自己用 Python 逐帧解码再转成图像喂给 Tk，每帧都要编码 + 拷贝，那才是卡顿的来源。
> 接口按 `mfplay.h` 的 vtable 下标直接调，零第三方依赖、exe 体积不增加、不联网。
> 万一系统缺 `mfplay.dll`，会自动退回「切出 MP4 交给系统播放器」，功能不至于没有。
>
> 细节：视频放进一个自建的子窗口（左右各留 70px、下方留 34px 给进度条），所以不会盖住两侧的翻页按钮；
> 松开鼠标的判断走 `GetAsyncKeyState`，因为鼠标一旦落在视频窗口上，Tk 就收不到 ButtonRelease 了。
> 这个子窗口的底色特意设成查看器同款深色，并且**要等解码器真的送出画面了才显示** ——
> 否则系统窗口类的默认白底会先闪一块白板出来。
>
> 这个子窗口的位置和尺寸**每次 `<Configure>` 都要重摆一遍**（`InlineVideo.fit` → `MoveWindow`）。
> 子窗口不会自己跟着父窗口变，只在建的时候算一次的话，窗口一改大小画面就还是原来的尺寸 ——
> 而且查看器刚打开时 canvas 可能还没算出尺寸，那时建出来的窗口只有 16x16，全靠这一步纠正。

> 实测你这个库：1691 张 JPEG 里 **629 张是动态照片**（37%），视频段通常占文件的一半左右。
> 也就是说「按住看动图」不是一个边角功能，是能给三分之一照片解锁的内容。

## 视频（`.mp4`）

网格里视频格子显示**首帧缩略图**（和资源管理器里看到的是同一张）。双击打开大图后，
视频**同样在这个窗口里直接播**，不跳系统播放器。

- 进到这一张就自动开播（不用长按）
- **点一下画面暂停，再点一下继续**；播完就停在最后一帧，**不会自动重播**
- 视频下方有一条**进度条**，随播放推进（播完画满）；**按住拖动可以跳到任意位置**
  （条只有 4px 高，上下各给了 8px 的点击容差）
- 松开鼠标**不会**把它停掉 —— 和动态照片不同。一段视频几十秒，跟着鼠标走没法看
- `←` `→` 翻页时自动收掉上一段
- 改变查看器窗口大小时，视频画面**跟着缩放**（子窗口不会自己变，每次 `<Configure>` 都重摆一次）

想交给系统播放器时，右键缩略图 → **用系统程序打开**。

播放走的是和动态照片同一套 `mfplay.py`，区别只是源文件：动态照片要先从 JPEG 尾部把 MP4 切出来
（`library.extract_motion`），视频文件直接给路径。

> **首帧是怎么来的**：走 Windows Shell 的缩略图提供程序（`IShellItemImageFactory::GetImage`），
> 也就是资源管理器显示视频封面用的同一套东西 —— 零依赖、不用自己搭解码器
> （用 Media Foundation 的 `IMFSourceReader` 自己抓帧要多写一百多行 ctypes）。
> 拿回来的 `HBITMAP` 用 `GetDIBits` 转成 PIL 图，`BGRX` 直接喂给 `Image.frombuffer`。
> 系统没装该格式的解码器时返回 `None`，格子退回 **▶ 视频** 占位。

> **进度条怎么来的**：`IMFPMediaPlayer::GetPosition` / `GetDuration`。
> 签名是 `(REFGUID guidPositionType, PROPVARIANT *pv)` —— **不是** `(LONGLONG *)`，
> 早年 MSDN 文档写错过，照那个写会一直拿到 0。`guidPositionType` 传 `MFP_POSITIONTYPE_100NS`
> （全零 GUID），回来的是 `PROPVARIANT`，实测 `vt` 是 `VT_UI8`，单位 100 纳秒。

> **踩过的坑**：传给 MFPlay 的源一开始是 `file://` URL，路径里的中文被百分号编码成 `%E8%A7%86…`，
> 而 MF 的 URL 解析器不按 UTF-8 还原，带中文名的文件直接报 `0x80070002`（找不到文件）。
> 动态照片之所以一直没暴露这个问题，是因为它切出来的临时文件叫 `PhonePhotoBackup_motion.mp4`，纯 ASCII。
> 现在改成直接给绝对路径（走 Win32 文件 API），Unicode 一切正常。
> 你库里的 `QQ视频_xxx.mp4` 就是这类 —— 注意微信/QQ 录像即使落在 `DCIM/` 下也照常备份。

## 打不开 / 显示不出来的图片

两种情况最常见，**都不是应用坏了**。现在应用会直接告诉你属于哪一种。

### 1. 云盘上的「仅在线」文件

OneDrive、坚果云这类网盘的「按需文件」在本地只是一个占位符，**一个字节的数据都没有**
（文件属性带 `RECALL_ON_DATA_ACCESS`）。网盘客户端没在跑的时候，读它必然失败：

```
底层：Windows 错误 362  ERROR_CLOUD_FILE_UNSUCCESSFUL
Python：OSError [Errno 22] Invalid argument
```

实测你机器上：OneDrive 没开时，`OneDrive\Microsoft Edge Drop Files\` 里 7 张图全都读不出来
（其余 145 个本机文件都正常）。

处理方式是「认出来，不硬读」：

- 扫描时打标记，**不去读**：不生成缩略图、不往 `error.log` 里刷记录、不让线程白等超时
- 网格格子里显示 **☁ 仅在线**（而不是一个永远转不出来的省略号）
- 打开大图会说明情况，并告诉你怎么解决
- **启动网盘客户端**后点顶栏 **刷新**（或 **更多 → 重新扫描**），它们就正常了

> 网盘客户端没运行时，资源管理器里双击同样打不开 —— 这不是应用的问题。

### 2. HEIC / HEIF（扩展名却写着 .jpg / .png）

iPhone 和部分安卓默认拍 HEIC。Pillow 不自带这个解码器，所以以前只会报
`cannot identify image file`。全库扫下来，你库里有 **13 张**这种：

| 扩展名 | 张数 | 真实文件头 |
|---|---|---|
| `.jpg` | 8 | `ftyp heic` / `ftyp mif1` |
| `.png` | 4 | 同上 |
| `.heif` | 1 | `ftyp heic` |

扩展名和真实内容对不上 —— 基本都是微信 / QQ 保存下来的。

**现在的处理**：Pillow 解不开时自动**退回 Windows 系统解码器**
（`IShellItemImageFactory`，和资源管理器显示缩略图用的是同一套），只要系统装了
「HEIF 图像扩展」就能正常显示，大图右下角会标 **● 系统解码器预览**。

真损坏的文件（两边都解不开）才会显示「无法显示这张图片」，详细原因记在程序旁边的
`error.log` 里。

## 装在哪

程序本体放在 `D:\PhonePhotoBackup\PhonePhotoBackup.exe`，**桌面上只放一个快捷方式**「手机照片备份」，双击即用。
运行过程中产生的文件（`config.json`、`error.log`、`.adbtmp\`、`.adb\`）都留在这个文件夹里，不会跑到桌面上。

> **`.adb\` 是什么**：随包分发的 adb 会被复制一份到这里，实际跑的是这一份（约 8 MB）。
> 为什么要多此一举：单文件 exe 每次启动都把资源解包到一个临时目录（`_MEIxxxxx`），
> 程序退出时由 PyInstaller 删掉。而 adb 第一次运行会常驻一个 server 进程，
> 那个进程锁住的正是它自己的 exe —— 锁在临时目录里，临时目录就删不掉，
> 退出时弹一个 `Failed to remove temporary directory` 的警告框。
> 复制到固定位置后 server 锁的是 `.adb\adb.exe`，临时目录每次都能干净删掉。

> ⚠️ **exe 必须待在可写目录**（D 盘任意文件夹、文档都可以），**不要放进 `C:\Program Files`**。
> 单文件 exe 启动时要在**自己所在目录**解包，只读目录会导致启动失败并弹出
> "Could not create temporary directory!"。详见「常见问题」。
> 要换位置就把**整个 `D:\PhonePhotoBackup` 文件夹**搬走，再重建桌面快捷方式即可。

                                  ← 之后「更多 → 更改备份目录」随时可改

├── .thumbcache\                 ← 缩略图缓存，随时可删，下次自动重建

**为什么再分四类**：`DCIM/` 里其实混着相机照片、截图、录屏，还有游戏截图、支付宝、
扫描全能王那些 app 生成的图。分开放，找东西不用在一堆杂图里翻。

`config.json` 与 exe 放在一起，记住备份目录，以及每台手机对应哪个目录名。

## 备份范围

**手机媒体库里的照片和视频全收** —— 相机、截图、录屏、微信/QQ 收发的图、下载的、
互传接收的，只要在系统媒体库里都会被备份，并按来源分进上面那四类。

分类按手机上的目录判断，各家不一样的地方都认：

| 归到哪 | 认这些位置（大小写不敏感） |
|---|---|
| `Camera` | `DCIM/Camera/` |
| `Screenshots` | `DCIM/Screenshots/`、`Pictures/Screenshots/` |
| `ScreenRecorder` | `DCIM/ScreenRecorder/`、`Pictures/Screenrecords/`、`Movies/Screenrecords/` |
| `Other` | 其余全部（微信、QQ、抖音、互传、下载……） |

> 实测一台红米 K80 Ultra：媒体库 2531 个，其中相机 1654、截图/录屏 208、
> 其余 669 个是微信 QQ 下载互传的。全收之后库是 20.4 GB。

想改范围就改 `backup.py` 里的 `BACKUP_PREFIXES`（现在是空的 = 全收）
和 `_CATEGORY_RULES`（分类规则）。

### 「同一个文件不备份第二遍」

判重是**跨设备、跨目录**的：只要库里已经有**同名同大小**的文件，不管它在哪台设备、
哪个日期目录下，都不会再拉第二份。所以：

- 同一台手机换 USB / 无线连接，不会重复
- 中途断了重跑，已拉完的自动跳过
- 归类方式以后要是变了，也不会因此多出一份

> 判重只比「文件名 + 字节大小」，不比内容哈希。不同照片同名同大小是极罕见的情况，
> 真遇到了再加校验。

## 安全说明（重要）

- **电脑上的任何操作都不会影响手机。** 应用只读手机，没有删除、移动、上传手机的代码路径。自检里有一条会扫描源码中所有 adb 调用，一旦出现 `push` / `rm` / `mv` / `mkdir` / `delete` / `uninstall` 就报错。
- **无线连接只负责"接上"，不碰数据。** `pair` / `connect` / `disconnect` 都在独立的 `wireless.py` 里，单独自检；真正搬文件的还是 `backup.py` 那套已经跑熟了的 `pull`。
- **删除只作用于电脑上的副本**：右键缩略图 → 「移到回收站」，进的是 Windows 回收站，可以还原。
- **备份目录不许选盘根 / 用户主目录 / Windows 目录**：「把老照片归入设备」会在备份目录下按 `<年>/<年-月-日>/` 找文件并搬进设备目录，根选得太靠上就可能动到自己的照片，所以这几类在「更改备份目录」处直接被挡下。
- **判断"是否已备份"只比较文件名 + 字节大小**，不会因为同名就覆盖；同名不同文件会自动加 `_1`、`_2` 后缀。
- 相册里的**拍摄时间取自手机媒体库**（Android 从 EXIF 提取），所以按年月日归档是按真实拍摄时间，不是拷贝时间。

## 常见问题

**`adb devices` 看不到手机 / 界面显示"未检测到手机"**
1. 数据线是数据线（不是只能充电的线）
2. USB 用途选「文件传输 / MTP」，别选「仅充电」
3. 开发者选项里 USB 调试已打开
4. 拔掉重插，手机弹出授权框时点「允许」
5. 小米/红米：设置 → 我的设备 → 全部参数与信息 → 连点「OS 版本」7 次可进开发者模式

**华为 / 荣耀手机上找不到「无线调试」**
不是你的问题 —— 这两个品牌的部分系统（EMUI 10.0–15.0、HarmonyOS 2.0–4.3、
Magic UI 4.1 等）**压根没有这个设置项**，官方文档写明了。这类机器请用数据线。
HarmonyOS NEXT（5/6）已经不再是 Android，**adb 完全不认**，无解。

**无线面板说「暂时没发现设备」**
1. 手机和电脑必须在**同一个 Wi-Fi** 下（手机连 5G、电脑插网线到同一台路由器也可以）
2. 手机上「无线调试」得开着 —— 有些机型重启后会自己关掉
3. 路由器开了 AP 隔离 / 访客网络的话，设备之间互相看不见，mDNS 也发现不了 → 手动填手机上显示的 `IP:端口`
4. 首次必须先配对：在手机上点「使用配对码配对设备」，等 6 位数字出来后**再点一次「重新发现」**

**备份到一半提示「手机已断开」**
见「无线备份」里的「掉线会怎样」。已拉完的文件都在，重新连上再点一次「开始备份」即可。

**用无线时手机别一直息屏**
部分机型息屏后会掐掉 Wi-Fi 省电，备份就断了。跑大批量时建议插着充电线、把屏幕超时调长一点。

**启动时弹出 `Could not create temporary directory!`**
说明 exe 所在目录不可写。把它移到桌面、文档或 D 盘任意文件夹再运行。
本程序特意改成在**自身所在目录**解包（PyInstaller 的 `--runtime-tmpdir "."`），就是为了绕开某些机器上 `%TEMP%` 权限异常导致启动失败的问题 —— 代价是 exe 所在目录必须可写。

**备份中途拔了线**：重新插好，再点一次「开始备份」，已拉完的会自动跳过。

**某些格子没有缩略图**：HEIC 需要系统装 HEIF 扩展；视频若显示 **▶ 视频** 占位，说明系统里没有能解这个格式的缩略图提供程序（`shellthumb.frame` 返回 `None`）。这类文件本身照常备份，双击打开大图，视频会在窗口内播放。

**一次要备份很久**：首次全量本来就慢（实测约 20 MB/s）。进度和速率在状态栏实时显示。
